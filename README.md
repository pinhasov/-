# לולה פדיקור – מערכת קביעת תורים

מערכת מלאה בעברית לקביעת תורים אצל לולה, הכוללת **ממשק לקוחה** ו**מערכת ניהול** ללולה ולאבי בלבד.
המערכת נפתחת מקישור בדפדפן, ניתנת להתקנה במסך הבית כאפליקציה (PWA), ועובדת מול מסד נתונים מרכזי אחד.

## מה המערכת עושה

### ממשק הלקוחה
* מסך פתיחה עם שם העסק, מלל פתיחה, כפתור "לקביעת תור" וכפתור "התורים שלי".
* בחירת טיפול מתוך כרטיסים הכוללים שם, תיאור, משך ומחיר.
* **לוח שנה מלא** – מעבר בין חודשים, כל ימי החודש מוצגים, תצוגה מימין לשמאל מיום ראשון.
* בחירת יום מציגה **מיד** את כל שעות אותו היום: פנוי / תפוס / לא זמין.
* חישוב זמינות לפי משך הטיפול – טיפול של 90 דקות לא יוצג כשיש רק 60 דקות פנויות.
* טופס פרטים קצר, מסך סיכום ואישור סופי.
* הוספת התור ליומן הטלפון (ICS / Google / Outlook) כולל תזכורת.
* קישור אישי ומאובטח לצפייה, שינוי או ביטול התור.
* הצטרפות לרשימת המתנה כשיום מסוים מלא.

### מערכת הניהול (לולה ואבי בלבד)
* יומן בתצוגה יומית, שבועית וחודשית.
* הוספה, עריכה, העברה, ביטול ומחיקה של תורים.
* חסימת ימים ושעות, פתיחת שעות חריגות והגדרת חופשות.
* ניהול טיפולים: שם, תיאור, מחיר, משך, זמן מעבר, תמונה, אישור ידני ומקדמה.
* הגדרת שעות פעילות שונות לכל יום בשבוע, כולל הפסקות.
* כרטיס לקוחה עם היסטוריית תורים והערות פנימיות.
* רשימת המתנה, יצוא ל-CSV, תיעוד פעולות ניהול והגדרות מערכת.

## התקנה והפעלה

**דרישה יחידה: Node.js גרסה 22.5 ומעלה.** אין תלות בחבילות חיצוניות כלל.

```bash
git clone <כתובת המאגר>
cd lola-booking
npm run seed        # יצירת טיפולים ראשוניים ושני משתמשי ניהול
npm start           # הפעלת השרת
```

המערכת תעלה בכתובת:

| כתובת | ייעוד |
|---|---|
| `http://localhost:3000` | ממשק הלקוחה |
| `http://localhost:3000/admin` | מערכת הניהול |
| `http://localhost:3000/t/<קוד>` | קישור אישי לניהול תור |

משתני סביבה אפשריים:

| משתנה | ברירת מחדל | תיאור |
|---|---|---|
| `PORT` | `3000` | פורט השרת |
| `HOST` | `0.0.0.0` | כתובת ההאזנה |
| `DB_PATH` | `data/lola.db` | מיקום מסד הנתונים |
| `TZ_NAME` | `Asia/Jerusalem` | אזור הזמן של העסק |
| `LOG_REQUESTS` | `0` | `1` להדפסת כל הבקשות ללוג |

## כניסה ראשונה למערכת הניהול

הפקודה `npm run seed` יוצרת שני משתמשי ניהול – **lola** ו-**avi** – ומדפיסה למסך סיסמאות אקראיות.
יש לשמור אותן במקום בטוח ולהחליף סיסמה לאחר ההתחברות הראשונה (לשונית "הגדרות" ← "החלפת סיסמה").

ניתן גם לקבוע סיסמאות מראש:

```bash
LOLA_PASSWORD='סיסמה-חזקה' AVI_PASSWORD='סיסמה-אחרת' npm run seed
```

הוספת מנהל נוסף או איפוס סיסמה:

```bash
npm run create-admin -- --name "לולה" --username lola --password "סיסמה-חדשה"
npm run create-admin -- --username avi --reset-password "סיסמה-חדשה"
```

> ללקוחה אין אפשרות להירשם כמנהלת. משתמשי ניהול נוצרים אך ורק מהשרת.

## מדריך הפעלה ללולה ולאבי

**איך מוסיפים טיפול חדש?**
לשונית "טיפולים" ← "טיפול חדש" ← למלא שם, משך ומחיר ← "שמירה". הטיפול יופיע מיד ללקוחות.

**איך משנים מחיר או משך טיפול?**
לשונית "טיפולים" ← "עריכה" ← לעדכן ← "שמירה". השינוי משפיע על תורים חדשים בלבד.

**איך משנים שעות עבודה?**
לשונית "שעות פעילות" ← לכל יום ניתן להוסיף או להסיר טווחי שעות ← "שמירת שעות הפעילות".
יום ללא טווחים = יום סגור. שני טווחים באותו יום (למשל 09:00–12:00 ו-16:00–19:00) יוצרים הפסקה.

**איך חוסמים יום או כמה שעות?**
לשונית "חסימות וחופשות" ← לבחור סוג "חסימה" ← תאריך ← להשאיר את השעות ריקות לחסימת יום שלם,
או למלא "משעה/עד שעה" לחסימה חלקית ← "הוספה".

**איך מגדירים חופשה?**
אותה לשונית, סוג "חופשה", תאריך התחלה ותאריך סיום.

**איך פותחים יום שבדרך כלל סגור?**
אותה לשונית, סוג "פתיחת שעות נוספות", תאריך ושעות.

**איך מוסיפים תור שנקבע בטלפון?**
לשונית "יומן" ← "הוספת תור" ← לבחור טיפול, תאריך ושעה ולמלא שם וטלפון.
השעה נחסמת מיד ללקוחות אחרות.

**איך מבטלים או מעבירים תור?**
לשונית "יומן" או "תורים" ← "ביטול" / "העברת מועד". ביטול מחזיר את השעה לזמינות באופן מיידי.
לולה ואבי רשאים לשנות או לבטל כל תור, גם אחרי המועד שבו הלקוחה כבר אינה יכולה לעשות זאת.

**איך מוציאים דוח?**
לשונית "תורים" ← לבחור טווח תאריכים וסטטוס ← "יצוא ל-CSV" (נפתח ישירות ב-Excel).

**איך מוסיפים את המערכת למסך הבית בטלפון?**
לפתוח את הקישור בדפדפן ← בתפריט הדפדפן לבחור "הוספה למסך הבית".

## הגדרות המערכת

לשונית "הגדרות" במערכת הניהול. אין צורך בפנייה למפתח כדי לשנות אותן.

| הגדרה | משמעות |
|---|---|
| שם העסק / כותרת / מלל פתיחה | הטקסטים שהלקוחה רואה |
| כתובת, טלפון, וואטסאפ, לוגו | פרטי יצירת קשר במסך הפתיחה |
| כתובת האתר | משמשת לבניית הקישורים האישיים לניהול תור |
| מרווח בין שעות מוצגות | כל כמה דקות מוצגת שעה אפשרית (ברירת מחדל 15) |
| זמן מינימלי להזמנה מראש | כמה שעות מראש חייבת הלקוחה לקבוע |
| עד כמה ימים קדימה היומן פתוח | טווח ההזמנות העתידיות (ברירת מחדל 90) |
| עד כמה שעות לפני ניתן לבטל | מדיניות הביטולים (ברירת מחדל 24) |
| אישור אוטומטי של תורים | כבוי = כל תור ממתין לאישור לולה |
| רשימת המתנה פעילה | הצגת רשימת המתנה ביום מלא |
| גביית מקדמה פעילה | הבסיס לתשלומים – ראו למטה |
| מדיניות ביטולים / תנאי שימוש / פרטיות | הטקסטים המשפטיים המוצגים ללקוחה |

### מקדמה ותשלום (שלב שני)
מבנה הנתונים מוכן: לכל טיפול ניתן להגדיר `ללא מקדמה / סכום קבוע / אחוז מהמחיר / תשלום מלא מראש`,
וסכום המקדמה נשמר בכל תור. בשלב הראשון ההגדרה **כבויה** (`payments_enabled = 0`).
חיבור לסליקה בעתיד אינו מחייב בנייה מחדש – רק הוספת שלב תשלום לפני שמירת התור.

### התראות (שלב שני)
בשלב הנוכחי אין SMS ואין שירות בתשלום. הלקוחה מוסיפה את התור ליומן הטלפון ומקבלת ממנו תזכורת,
ולולה ואבי רואים כל תור חדש מיד במערכת הניהול. הוספת WhatsApp / Push / דוא"ל בהמשך תיעשה
בנקודה אחת בקוד (`src/bookings.js`, לאחר שמירת התור).

## מנגנון חישוב הזמינות

שעה מוצגת כפנויה רק אם **כל** התנאים מתקיימים (`src/availability.js`):

1. היום פתוח לפי שעות הפעילות הקבועות, או נפתח בחריגה.
2. אין חופשה או חסימה החופפת לטיפול.
3. משך הטיפול כולו נכנס בתוך שעות הפעילות.
4. אין חפיפה לתור קיים – כולל **זמן המעבר** שהוגדר לטיפול.
5. השעה עדיין לא עברה, ומכובד הזמן המינימלי להזמנה מראש.
6. התאריך נמצא בטווח שבו היומן פתוח.

לפני שמירת התור מתבצעת **בדיקה חוזרת בתוך טרנזקציה** (`BEGIN IMMEDIATE`), כך ששתי לקוחות
שלוחצות "אישור" באותו רגע – רק אחת מהן תקבל את השעה, והשנייה תקבל הודעה ברורה בעברית.

## אבטחה ופרטיות

* סיסמאות מנהלים נשמרות מוצפנות (scrypt עם מלח אקראי) – לעולם לא כטקסט גלוי.
* הפעלת מנהל נשמרת בעוגייה `HttpOnly` + `SameSite=Lax`, ותוקפה 14 יום.
* כל פעולה משנה במערכת הניהול מחייבת כותרת ייעודית (הגנה מפני בקשות חוצות אתרים).
* הקישור האישי לניהול תור מבוסס אסימון אקראי של 24 בתים (192 ביט).
* ללקוחה אין גישה לשום נתון של לקוחה אחרת: רשימת השעות מחזירה "תפוס" בלבד, ללא שם או טלפון.
* הגבלת קצב על קביעת תור, ביטול, רשימת המתנה והתחברות.
* תיעוד פעולות ניהול מהותיות ב-`audit_log`.
* מחיקת פרטי לקוחה לפי דרישה: כרטיס הלקוחה ← "מחיקת פרטים" (התורים נשמרים ללא זיהוי).
* בהרצה מאחורי HTTPS העוגייה מסומנת אוטומטית כ-`Secure`.

## העלאה לאוויר (Production)

### פריסה ב-Railway (הפריסה הפעילה)

המערכת פרוסה בפרויקט **lola-booking** בחשבון Railway, מהענף
`claude/lola-pedicure-booking-system-nciwul` של המאגר `pinhasov/-`.
כל דחיפה (push) לענף הזה מפעילה פריסה מחדש אוטומטית.

**משתני הסביבה שמוגדרים בשירות:**

| משתנה | ערך | תפקיד |
|---|---|---|
| `DB_PATH` | `/data/lola.db` | מיקום מסד הנתונים |
| `DATA_DIR` | `/data` | תיקיית הנתונים |
| `TZ` / `TZ_NAME` | `Asia/Jerusalem` | שעון ישראל |
| `NODE_ENV` | `production` | סביבת הרצה |
| `AUTO_SEED` | `1` | אתחול ראשוני בלבד – פועל רק כשאין עדיין משתמשי ניהול |
| `LOLA_PASSWORD` / `AVI_PASSWORD` | סודי | סיסמאות ההתחברות הראשוניות |

> ⚠️ **חובה: דיסק קבוע (Volume).**
> ללא Volume, מסד הנתונים נמחק בכל פריסה מחדש – כלומר כל התורים ייעלמו.
> להוספה: לוח הבקרה של Railway ← השירות `lola-booking` ← לשונית **Variables/Settings** ←
> **Volumes** ← **New Volume** ← נתיב עגינה (Mount path): `/data` ← שמירה.
> Railway יפרוס מחדש, והמערכת תיצור את הטיפולים ומשתמשי הניהול מחדש על הדיסק הקבוע.
> מרגע זה כל התורים נשמרים לצמיתות.

**חיבור דומיין משלכם** (למשל `appointments.lola.co.il`): לוח הבקרה ← השירות ←
**Settings** ← **Networking** ← **Custom Domain**, ולהוסיף אצל ספק הדומיין את רשומת ה-CNAME
ש-Railway מציג. לאחר מכן כדאי למלא בהגדרות המערכת את שדה "כתובת האתר".

### פריסה על שרת משלכם

1. להתקין Node.js 22+ על השרת ולהעתיק את הפרויקט (לדוגמה ל-`/opt/lola`).
2. להריץ `npm run seed` פעם אחת ולשמור את פרטי הגישה.
3. להגדיר שירות שעולה אוטומטית, לדוגמה systemd:

```ini
[Unit]
Description=Lola Booking
After=network.target

[Service]
WorkingDirectory=/opt/lola
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning src/server.js
Environment=PORT=3000
Environment=NODE_ENV=production
Restart=always
User=lola

[Install]
WantedBy=multi-user.target
```

4. להעמיד מולו שרת עם HTTPS (Nginx / Caddy) ולהפנות אליו את הדומיין,
   למשל `appointments.lola.co.il` או `lola.co.il/book`.
   יש להעביר את הכותרות `X-Forwarded-Proto` ו-`X-Forwarded-Host`.
5. בלשונית "הגדרות" למלא את **כתובת האתר** – כדי שהקישורים האישיים ייבנו נכון.

הקישור נפתח בדפדפן ללא הורדת אפליקציה, וניתן להוספה למסך הבית כ-PWA.
אם בעתיד תפותח אפליקציה נפרדת לחנויות, היא תעבוד מול אותו API ואותו מסד נתונים בדיוק.

### ציבורי

## בעלות על המערכת

הקוד, העיצוב, מסד הנתונים וכל המידע שייכים לבעלי העסק.
כל ניהול הזמינות, הטיפולים, המחירים והשעות מתבצע ממערכת הניהול, ללא תלות במפתח.
ניתן להעביר את המערכת בכל עת למפתח אחר: המערכת בנויה מקוד סטנדרטי ללא תלויות חיצוניות,
ומסד הנתונים הוא קובץ SQLite אחד שניתן להעתיק, לגבות וליצא.
